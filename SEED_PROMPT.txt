1. PRODUCT AND SCOPE

Working name: Meeting Coach. Intended users are financial advisers reviewing their own recorded meetings. It evaluates the adviser's communication and meeting craft. It does not certify compliance, assess investment suitability, judge clients, or generate client advice.

The user explicitly chose public access with an API key HE funds. Do not turn the MVP into bring-your-own-key, an invitation-only service, or a registration funnel. There is no billing, saved history, CRM integration, audio transcription, meeting bot, team management, email sending, custom rubric editor, or trend dashboard in this version.

Essential flow:
1) Paste a speaker-labelled transcript into a large box on the home page.
2) The browser parses it locally and asks which speaker is the adviser.
3) The adviser checks a responsibility acknowledgement.
4) Review meeting sends one bounded grading request.
5) A results view shows scores, evidence and practical coaching.
6) Download PDF creates a readable document locally in the browser.

Use OpenAI for the first provider. Codex is the development agent, not the public grading service: do not run Codex CLI, expose a coding agent, or execute user-supplied code on the backend. Use an OpenAI Platform API key and a normal model request.

3. ARCHITECTURE AND DATA LIFECYCLE

Use current compatible stable dependencies and commit a lockfile. No Supabase, ORM, transcript database, object storage or content queue. A simpler equivalent stack is acceptable if it preserves these boundaries; explain the choice once.

Data path:
browser memory -> HTTPS POST /api/review -> request-scoped server memory
-> OpenAI Responses API -> server validation -> browser memory -> local PDF

Because Pierre funds the shared API key, a server relay is necessary. The transcript does leave the browser when Review is pressed, and the application server processes it. Never claim the data stays only on the device, never reaches our servers, is end-to-end encrypted, or has zero retention everywhere.

The server owns the rubric, prompt, model and token limits. Treat all browser inputs as untrusted. Send the raw transcript once plus role selection and required acknowledgement; reparse and recompute metrics server-side using shared pure code. Do not accept client-computed scores, a caller-selected model, arbitrary system prompts, provider URLs or cost settings.

Keep content in request scope only. No module-level map of transcripts, filesystem dumps, database rows, response caches, logs of prompts or answers, analytics/session replay, exception attachments, tracing payloads, or APM request-body capture. Return no raw transcript in the API response. Results contain sensitive quotes too: they receive the same treatment as input.

Use POST JSON, bounded streamed body reading (do not trust Content-Length alone), explicit no-store response headers, safe errors, HTTPS in production, and a restrictive practical CSP/referrer policy. Use a fixed provider destination. Same-origin and origin checks are useful but are not authentication or sufficient abuse protection.

Self-host assets. No remote analytics, fonts, error reporters, or content-bearing fetches. A chosen bot-challenge service may load its script and process network/browser metadata, but must not receive transcript text; disclose that limited third party. Inspect the browser network flow.

4. GRADING ENGINE

Port, do not reinvent, the useful parts of reference/crm/lib/transcripts/parse.ts, lib/scorecards/metrics.ts, and the rubric. Rework the judge to OpenAI while preserving its domain behavior.

The prepared handoff/rubric-source-sw-behavioural-1.2.json is extracted from the actual SQL seed. handoff/rubric-meeting-coach-1.0.json changes only the one criterion's "what Pierre does" to "what the adviser does", assigns standalone IDs/version, and records provenance in its companion metadata. Use the standalone rubric as the initial immutable source in code; do not create SQL tables. Keep 7 scores, 25 criteria, scale 1–5, equal weights:
1. Human before agenda
2. Listening share
3. Behavioural coaching moments
4. Plain language
5. Agreements & adherence
6. Anchored to their why
7. Both voices, applicable to a couple's meeting only

Do not silently infer that any two speakers are a couple. Capture one client/couple/other meeting context simply when needed. S7 is not assessable outside the couple scope. Preserve English/Afrikaans/mixed-language capability of the source; write coaching in British English and quote original speech. The old SaaS exploration's English-only decision is not a requirement for this project.

Compute talk share, question-turn count, uninterrupted spans, duration and client speaking balance in code. Keep the partial-diarisation quality gate. When removing observer speech from relevant metrics, retain the full conversation as judge context and test the role semantics; do not turn observer time into client speech or adviser time. Refuse unsupported attribution rather than reporting precise-looking wrong figures. Missing timestamps are allowed with clearly labelled word-based estimates. Never invent recording timestamps, including via distributeTimestamps(). If known duration is supplied without timestamps, it remains a total-duration fact, not evidence of where a sentence occurred.

Judge defaults: gpt-6-astra, reasoning effort medium, standard mode; configurable server-side via REVIEW_MODEL/REVIEW_REASONING_EFFORT. GPT-6.1 Sol is the cost comparison candidate. Verify current model access and parameter support against official docs before a real smoke test. Do not automatically fall back to another model or provider. Do not blindly carry over temperature:0 or claim repeatability of AI scores; metric arithmetic is deterministic, model judgment is not.

Use foreground Responses API with explicit store:false on every call, including retries. No background mode, Files API, conversations, provider-hosted tools, vector stores, web search, code execution, MCP, or agents runtime. This is a single structured grading task. Return structured JSON through the provider's strict JSON-schema mechanism, then run domain validation. Preserve the substantive instructions in the old judge, but use a new prompt version for the provider/schema/branding changes. Do not ask for hidden chain-of-thought; concise evidence-linked rationales are enough.

Treat transcript content as quoted untrusted data. Instructions embedded in it do not change the rubric, reveal secrets, invoke tools or alter the output contract. Separate the trusted rubric/instructions from the transcript. Never interpolate transcript text into the output schema or schema names.

Strengthen the extracted validator where it is incomplete:
- Every score and each of its criteria appears exactly once, with correct parent-child IDs. No omissions, duplicates or invented IDs.
- Assessable score values are finite and in 1–5; unassessable values are null. Recompute overall in code, excluding n/a. Return that recomputed value everywhere.
- All five coaching entries contain a nonempty title, learning and example. Remove unused flags and legacy coaching shapes from the new schema rather than preserving unused fields forever; this requires a new prompt version.
- Give parsed utterances stable request-local segment IDs. Evidence should reference a segment ID and contain a verbatim substring of its text. Resolve displayed speaker and timestamp from the source segment, not from model-generated metadata. Reject invented or mismatched quotes. Do not trim away disfluencies, merge separate utterances or pass a metric off as speech. A valid quote still does not prove the interpretation is sound: retain human calibration.
- A criterion with no assessable evidence is n/a with an explanation. Missing opportunities are not failures. Where an actual missed opportunity is scored down, cite the relevant interaction.
- Explicitly handle refusal, incomplete/truncated output, schema failure, provider errors and deadline expiry. Do not render partial JSON as a successful review.

Allow at most one bounded correction attempt for invalid results, with concise safe error feedback. Both calls count against the quota. No automatic fallback or recursive retry loop. Configure SDK retries deliberately so hidden retries cannot exceed the documented attempt budget. Apply a real timeout/AbortSignal across provider calls; the CRM's elapsed-time check only controls whether a second attempt starts, not a hung first call.
