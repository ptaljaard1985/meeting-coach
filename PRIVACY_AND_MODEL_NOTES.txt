3. IMPLEMENTED APPLICATION DATA LIFECYCLE
- Paste/edit/parse happen in browser memory; paste does not transmit transcript content.
- Review sends transcript/roles through the hosting server to OpenAI. The optional title stays local.
- Transcript text, parsed segments, evidence, explanations and written coaching stay request-scoped on the server, then in active browser memory. No transcript/review content database, file archive, log, cache or recoverable meeting history is implemented.
- The browser creates a selectable-text PDF from the received review; download does not regrade or contact an external PDF converter. A downloaded file stays on the device.
- Navigation, Clear and page lifecycle handling release app session/download state. This is not forensic erasure and cannot retract accepted upstream work. Cancel attempts to abort but an accepted call can still be processed/billed.
- Production's shared abuse limiter retains short-lived pseudonymous network keys, opaque submission/call IDs and counters. Those expiring keys are distinct from the numerical analytics below.
- Host logs and Turnstile may retain network/operational metadata. The app sends no transcript text to Turnstile. Actual host body/response capture must be checked before launch.

4. OWNER-APPROVED NUMERICAL ANALYTICS — UNTIL DELETED
The owner requested request counts, timings and scores for their own analyses, then chose retention "until i delete them". This is an explicit exception to the original blanket no-result-storage wording: keep numerical metadata, never meeting text or written reviews.
With ANALYTICS_ENABLED=true and project Redis credentials, accepted live AI requests record an independent random analytics ID, start/finish dates, server processing duration, review/example type, configured model, prompt/rubric versions, fixed outcome, model-call attempts and returned numerical token counts. A successful validated review also contributes its overall and seven category scores. There are no names, titles, transcript text, quotes, coaching, raw errors, IP/network identifiers or submission/report IDs. Demo and rejected submissions are excluded.
Records use mc:{analytics}:records and mc:{analytics}:index in the existing Upstash service. Writes remove expiry and have no automatic cleanup or record cap. Keep records until explicit operator deletion; verify Redis persistence, capacity, eviction and backup lifecycle accordingly. There is no public analytics endpoint or dashboard.
Commands with server credentials:
  npm run analytics:export
  npm run analytics:export -- --out output/analytics/reviews.csv
  npm run analytics:delete -- --confirm-delete
Deletion targets only analytics keys, not quota/duplicate protections. ANALYTICS_ENABLED=false stops future collection without deleting old records. Let active requests finish before deletion to avoid subsequent writes. Clear does not delete these records. Exported CSV copies must be handled separately.
Analytics are best effort; storage failure does not discard a completed review. A running record may indicate interruption. A request can have two model attempts, and a failed call may lack usage; usageComplete=false prevents treating missing usage as zero cost. This is operational analysis, not an exact billing ledger. No live numerical records have been inspected or verified in this work. The last instructed demo mode does not collect them.
Responsibility notice version 2026-10-02.2 includes the numerical retention disclosure.
